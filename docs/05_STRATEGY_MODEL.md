# Quant Investment Platform — Strategy Model

## MVP Strategy

The first configuration-driven production candidate is `M_RD_504010_V2` (configuration `2`). It is the baseline for the MVP execution flow and must not be modified during subsequent factor research.

### Strategy construction

The strategy uses reusable technical features generated by `quant_features` and an immutable configuration snapshot containing factor groups, feature weights, directions, and enablement.

Current V2 factor-group allocation:

| Factor group | Weight |
|---|---:|
| Momentum | 40% |

Current V2 configured features:

- Momentum: `RETURN_20D` 15%, `RETURN_60D` 15%, `RETURN_252D` 10%
- Trend: `PRICE_VS_MA_20D` 8%, `PRICE_VS_MA_60D` 8%, `PRICE_VS_MA_252D` 9%
- Risk: `VOLATILITY_20D` 7% negative, `VOLATILITY_60D` 7% negative, `VOLATILITY_252D` 6% negative
- Drawdown: `DRAWDOWN_252D` 15% positive

Feature scores are percentile-ranked cross-sectionally by trading date. Negative-direction features have their percentile ranking inverted. Weighted feature scores are aggregated into factor-group scores and then into the composite strategy score.

## MVP Signal and Execution Semantics

The V2 configuration is explicitly configured as:

- `signal_frequency = WEEKLY`
- `entry_rule = NEXT_TRADING_DAY`
- `rebalance_rule = NEXT_SIGNAL`
- `top_n = 2`
- `position_weight = 0.50`

The weekly signal date is the **last available trading day of each calendar week** in the available ranking history.

On each signal:

1. Rank all eligible securities by composite score.
2. Select the top 2 securities.
3. Allocate 50% target weight to each selected security.
4. Enter on the next available trading day.
5. Hold those positions until the next weekly signal.
6. Change the portfolio only when the new signal requires a different target portfolio.

This is a **signal-based holding model**, not a fixed-duration or mechanical weekly rebalance model. If the same securities remain selected, no turnover is generated during the holding period.

## Warm-up Policy

The V2 configuration requires all 10 configured features to be available before a security can contribute a complete configured score. The first date on which all 10 configured features are available for a security is 2021-01-04.

The earlier period is treated as intentional feature warm-up/incomplete history for the MVP. No artificial backfill or feature-specific warm-up adjustment is introduced at this stage.

## Baseline Protection

`M_RD_504010_V2` is the MVP baseline. Factor optimization must create a new configuration/version rather than mutate the baseline configuration or its immutable snapshot.

The legacy `M_RD_504010` strategy remains preserved separately.

## Known V2 vs Legacy Difference

V2 is not an exact reproduction of the legacy strategy. In particular, the legacy path uses all-time drawdown while V2 uses `DRAWDOWN_252D`, and V2 constructs scores through the configuration-driven feature/group hierarchy.

Therefore performance differences between legacy and V2 cannot be attributed to signal cadence alone.
